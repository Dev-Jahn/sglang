Qwen3.8-Flash-Next checkpoints contain a large Qwen4-architecture n-gram PLE table. Use `--ple-storage disk` to keep its packed row image on local storage while SGLang holds selected exact rows in host memory. The implementation requires low-latency `O_DIRECT` storage and access to `/sys/dev/block` for logical-block-size validation. A local NVMe filesystem is recommended, although other local block-backed filesystems can provide the same interface with higher latency.

The first load creates one fingerprinted image per PLE layer and tensor-parallel rank under `--ple-disk-dir`. Later loads reuse an image only when its module prefix, configuration, shard manifest, sampled row data, and weight scale match the checkpoint. Each weight shard must carry its checkpoint basename, file size, and modification time. Disk mode rejects loaders that do not provide that source identity.

Disk mode constructs the full PLE weight on the meta device, so startup does not allocate the table on the GPU before creating its disk image.

## Prerequisites

Before launching the server, provide:

- Linux kernel 5.11 or later with `io_uring_setup`, `io_uring_enter`, and `io_uring_register` enabled; `kernel.io_uring_disabled` must permit the server process to create a ring
- `sglang-kernel` 0.4.6.post2 or later with the packaged `qwen4_ple_disk_fetcher` helper; the helper checks `io_uring` support on the running kernel
- A local filesystem that supports `O_DIRECT`
- A storage device with a logical block size no larger than 4096 bytes
- Access to `/sys/dev/block` so SGLang can verify the device logical block size
- `ple_embedding_dtype: float8_e4m3fn` in the model configuration and FP8 E4M3 checkpoint rows
- Free space for the raw row file and packed image during the first build

Disk storage does not support pipeline parallelism with `--pp-size > 1`, dLLM with `--dllm-algorithm`, DP attention with `--enable-dp-attention`, multi-layer EAGLE with `--enable-multi-layer-eagle`, or prefill CUDA graphs. DP attention is rejected because its token gathering can make an idle rank's captured PLE lookup consume staging from an earlier step. Multi-layer EAGLE uses graph runners that do not invoke the PLE replay hook. An enabled `--cuda-graph-backend-prefill` is rejected; the automatic setting disables prefill graphs while keeping decode graphs enabled.

The packed image stores 25 160-byte rows in each 4 KiB page. Its 96-byte page tail makes it about 2.4% larger than the row payload. The first build holds the full raw row file and packed image at the same time, so reserve slightly more than twice the row payload. After a successful install, SGLang removes the raw file.

On the measured dual RTX PRO 6000 TP2 host, first-build conversion of the two approximately 24.4 GiB rank images took 50.1 and 47.0 seconds. Storage throughput, checkpoint layout, and concurrent rank loading affect this time.

## When to use disk storage

Disk mode targets RAM-constrained, low-concurrency serving. In equal-commit NVFP4 TP2 tests with 512-token inputs and outputs, median TPOT was 1.9% higher at concurrency 1. With 32 prompts at concurrency 16, median output throughput was 9.0% lower and median TPOT was 7.5% higher. These tests used decode CUDA graphs, FlashInfer attention, Triton linear attention, and the FlashInfer CUTLASS FP4 and MoE backends on two RTX PRO 6000 GPUs. The image files were on an ext4 MegaRAID virtual SCSI volume, rather than a native NVMe namespace. Use pinned storage when host RAM is available and high-concurrency throughput is the priority.

## Launch a server

The measurements below used `RadixArk/Qwen3.8-Flash-Next-NVFP4`. The FP8
checkpoint `Qwen/Qwen3.8-Flash-Next-FP8` is an alternative.

```bash
python -m sglang.launch_server \
  --model-path RadixArk/Qwen3.8-Flash-Next-NVFP4 \
  --tp 2 \
  --ple-storage disk \
  --ple-disk-dir /mnt/local-nvme/qwen4-ple
```

This example starts with an empty static hot cache because it does not pass `--ple-disk-hot-frequency-file`. It uses the default 2 GiB dynamic cache budget.

Dynamic-cache hit frequencies are updated synchronously with vectorized sketch operations. Miss admission and row installation use the bounded background queue.

SGLang checks each 4 KiB image page against its stored CRC before using the rows. An incomplete install, older image format, or incompatible manifest produces an error that names the directory to delete before rebuilding.

Disk mode keeps decode CUDA graphs enabled. It disables prefill CUDA graphs and sets both `--cuda-graph-backend-prefill disabled` and `--disable-prefill-cuda-graph`. An explicitly enabled prefill graph backend is rejected after JSON, convenience, and legacy graph options have been resolved.

Set `--ple-disk-stats-log-interval N` to log cumulative storage and cache counters every `N` model steps. The default `0` disables these logs.

The hot and dynamic cache budgets are totals across all tensor-parallel ranks, PLE layers, and data-parallel replicas. SGLang divides each budget evenly among the corresponding embedding instances. Each layer has its own readers, staging buffers, caches, and executors.

The image fingerprint covers the selected model configuration, including the EOS token ID, plus source basename, file size, shard geometry, and up to 64 evenly spaced rows from each shard. The recorded modification time is excluded from the fingerprint. If the time changes while the sampled checkpoint content stays the same, SGLang reuses the existing image without materializing its rows again.

## Generate a static hot-row file

The static cache starts empty unless you pass `--ple-disk-hot-frequency-file`. First launch the server once to build the image. Each fingerprint directory contains a `ple-metadata.json` file with the PLE hash geometry and image fingerprint needed by the simulator. Tokenize your corpus into a headerless stream of little-endian signed 32-bit token IDs, with the model EOS token between documents. The current tool accepts `ngram_size: 3`. Run the source-checkout-only simulator with that metadata file, then relaunch the server with the generated file. The tool is not included in the Python wheel:

```bash
python scripts/ple_disk/hit_sim.py \
  --tokens /mnt/local-nvme/ple-corpus.i32 \
  --metadata /mnt/local-nvme/qwen4-ple/FINGERPRINT/ple-metadata.json \
  --work-dir /mnt/local-nvme/ple-counts \
  --budget-gib 8 \
  --tp-size 2 \
  --padding-divisor 128 \
  --output /mnt/local-nvme/ple-hot.bin
```

Use the `ple-metadata.json` from the fingerprint directory that contains the server's `rank0.bin` image. For a standard Qwen3.8-Flash-Next checkpoint, `--padding-divisor 128` matches `make_ngram_vocab_size_divisible_by` in the checkpoint configuration. The count stage keeps one `uint64` count array per hash head under `--work-dir`, about 2.5 GiB for the 16-head geometry, and counts tokens on a single thread.

Pass the result to the server:

```text
--ple-disk-hot-frequency-file /mnt/local-nvme/ple-hot.bin
```

Checkpoints with multiple PLE layers need one file per layer because each layer has different hash multipliers and an image-specific fingerprint. Generate each file with that layer's `ple-metadata.json`, then put `{layer}` in the server path. The field expands to the zero-based PLE layer index, for example `/mnt/local-nvme/ple-hot-{layer}.bin`.

The file starts with one 4 KiB metadata page. It contains the `PLHOT001` magic, format version, image fingerprint, `uint32-global-row-id` dtype, TP size, padding divisor, total row count, and each rank's vocabulary range, offset, and count. The remaining bytes are concatenated little-endian `uint32` global row IDs for each rank, ordered by decreasing training-corpus frequency. This ordering is part of the file contract because SGLang truncates each rank segment by position to fit `--ple-disk-hot-cache-gb`. SGLang validates the recorded rank geometry before sorting the retained rows into the rank-select cache. Static-cache warmup reads selected pages through the direct-I/O reader. With the default budget, restarts can issue up to 8 GiB of random 4 KiB direct reads across all rank and layer instances before the server becomes ready. The same rebuild runs synchronously when storage resumes after a weight reload or a memory release. It blocks the resume call until the selected rows have been read, and the server logs the rank, module, and budget when it starts.

## Read queue settings

`--ple-disk-max-read-pages` sets the page count for the decode `io_uring` and its staging area. Its automatic value is 1024 when the CUDA device uses the host page tables for pageable memory and 4096 on other CUDA devices. Set the flag directly when you need a smaller queue or memlock allocation. Each cold read computes one CRC32 in Python per 4 KiB page while holding the reader lock, so larger values also increase the maximum checksum work in one call.

Each completion wait uses a timeout of at most 100 ms. A native read has one 5.5-second `CLOCK_MONOTONIC` deadline across submission, interrupted-system-call retries, completion waits, and error draining. If the helper cannot account for submitted requests by that deadline, it marks the reader poisoned and requires a server restart. Shutdown first allows up to 5,000 busy retries of 1 ms, about 5 seconds, for the active read to leave its critical section. It then allows up to 50 waits of 100 ms, about 5 more seconds, to reap pending requests. The combined shutdown budget is about 10 seconds per reader. When that budget expires, the native reader and its staging allocation remain allocated for the process lifetime so the kernel cannot write into released memory.

`--ple-disk-prefill-read-pages` controls a separate prefill ring. Its maximum is 32,768 pages. SGLang clamps it to `--ple-disk-max-read-pages` and logs a warning when the requested value is larger. `--ple-disk-prefill-buffer-tokens` accepts up to 65,536 tokens.

## Host memory planning

The row arrays in the hot and dynamic cache tiers are CUDA-pinned host allocations. Their bitmap, tag, recency, and frequency-sketch metadata use pageable memory. The documented cache budgets total 10 GiB across ranks and layers, and the dynamic budget accounts for both rows and metadata. Prefill slots, future-ID staging, and transfer buffers add pinned allocations for each layer and rank. A retained transfer buffer covers the largest of 65,536 rows, `prefill buffer tokens * n-gram heads`, and `chunked prefill tokens * n-gram heads`. An 8192-token chunk with 16 heads retains 131,072 rows, or 20 MiB of pinned host memory plus its device buffer. Larger transfer buffers are released after the copy completes. Include these allocations in both host-RAM and memlock planning even on systems where CUDA registration is accounted separately from `RLIMIT_MEMLOCK`.

Without a frequency file the resident cache cost is the dynamic tier alone, 2 GiB by default across all ranks and layers. A populated static tier adds up to its configured budget, 8 GiB by default.

## Replay validation

Every staged decode replay carries a host-side generation number through prepare and wait. This check confirms that the hook staged work for the current replay and waited for the same generation. It does not inspect lookup IDs or row contents. Capture also verifies that the resolved language model and graph runner expose the supported replay-hook path. A captured graph key that reaches wait without same-step staging is an error.

The first CUDA graph replay after each capture compares the recomputed lookup IDs with the IDs captured by that graph. The device comparison copies one Boolean result to pinned host memory and the next host visit reads it after an event query. The check is one replay step behind, so the reported step's output has already been emitted when an error is raised. The error names the replay step and lookup-token count. Treat output since the last successful check as suspect. `SGLANG_PLE_DISK_GRAPH_LOOKUP_VALIDATION_INTERVAL=0`, the default, runs only the first-replay check. A positive value also checks every Nth replay: `1` checks every replay, `64` checks every 64th replay, and larger values reduce the diagnostic work proportionally.

`SGLANG_PLE_DISK_VALIDATE_GRAPH_STAGING=1` compares staged disk rows with the values consumed by the next replay. Row comparison is disabled by default. Both content comparisons depend on the replay hook; the capture-time runner check prevents disk mode from using a runner that skips it. Missing capture buffers are treated as programming errors.

## Run in a container

Docker's default seccomp profile does not allow the `io_uring_setup`, `io_uring_enter`, and `io_uring_register` system calls. Supply a custom seccomp profile that allows these calls, or use `--security-opt seccomp=unconfined` in a trusted environment. The host `kernel.io_uring_disabled` setting also applies inside the container. SGLang reports a blocked setup and exits. It does not change the storage mode automatically. Use `--ple-storage pinned` when the container policy or host sysctl cannot allow `io_uring`.

The `io_uring` fixed-buffer registration counts against `RLIMIT_MEMLOCK`. Set the container memlock ulimit high enough for every rank and PLE layer:

```text
registered bytes per rank and PLE layer = 4096 * (max read pages + active prefill read pages)
```

Each reader has one staging allocation and a small offset array. Include the staging allocation in host-memory planning:

```text
reader staging bytes per rank and PLE layer = 4096 * (max read pages + active prefill read pages)
```

The prefill term applies when `--ple-disk-prefill-buffer-tokens` is greater than zero. Leave room for other locked allocations made by the process. For Docker, `--ulimit memlock=-1` removes this limit; a finite limit at or above the required allocation also works. If registration returns `ENOMEM`, SGLang reports the attempted byte count and the flag that reduces it.

Systems where `pageableMemoryAccessUsesHostPageTables` is true use an unregistered staging area, so the `io_uring` staging bytes do not consume the memlock budget.

## Troubleshooting

- **Memlock limit:** `PLE io_uring buffer registration exceeded RLIMIT_MEMLOCK while registering N bytes; raise the memlock ulimit or lower --ple-disk-max-read-pages`. Raise the process or container memlock limit, or reduce the registered page count.
- **Container seccomp:** `PLE io_uring is blocked; common causes are the default container seccomp policy and kernel.io_uring_disabled. Allow io_uring or use --ple-storage pinned`. Allow all three `io_uring` system calls in the container profile.
- **Disabled io_uring:** `PLE io_uring is blocked; common causes are the default container seccomp policy and kernel.io_uring_disabled. Allow io_uring or use --ple-storage pinned`. Check `sysctl kernel.io_uring_disabled` on the host and choose a value that permits the server process.
- **Old kernel:** `PLE io_uring requires Linux kernel 5.11 or later; upgrade the kernel or use --ple-storage pinned`.

### Run the native helper test locally

From a source checkout, set `SGL_KERNEL_RUN_TESTS=1` when running `python/sglang/kernels/aot/build.sh`. This enables `SGL_KERNEL_BUILD_TESTS`, runs CTest in the local build container, adds `seccomp=unconfined`, and defaults `SGL_KERNEL_PLE_REQUIRE_IO_URING` to `1`. Set `TMPDIR` to a block-backed filesystem that supports `O_DIRECT`; the test reports an error with this requirement when the selected directory is unsuitable. The shared PR wheel workflow leaves these variables unset and uses the release CMake configuration.

## GB10 untested starting point

The following NVIDIA GB10 settings are an untested starting point derived from the device memory and pageable-memory properties. Start with `--mem-fraction-static 0.85` and `--max-running-requests 4`. This leaves a usable GDN state pool for Qwen4 while the PLE table uses disk storage. The automatic read-page limit is 1024 on GB10.

```bash
python -m sglang.launch_server \
  --model-path RadixArk/Qwen3.8-Flash-Next-NVFP4 \
  --ple-storage disk \
  --ple-disk-dir /mnt/local-nvme/qwen4-ple \
  --mem-fraction-static 0.85 \
  --max-running-requests 4
```
